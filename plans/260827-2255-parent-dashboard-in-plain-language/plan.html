F2 · high · a rule id that contains the child’s own words

engine.ts:143 builds `evasion.devoweled.${alert.token}` — an id constructed at runtime from a fragment of what the child typed, and absent from RULES.

Two decisions failed at once. The exhaustiveness test walks RULES, so it cannot see this id and passes while flags exist with no label. And if any path echoes the id — including a fallback added for debuggability — the guardian reads part of the child’s message, in the flags list, which is precisely the surface the reviewed prior art leaked.

Fix (D10): labels are keyed on the rule family. The dynamic suffix is stripped before any lookup, so the token stops existing at the boundary rather than being carefully avoided downstream.

F1 · high · the crisis card works by accident

engine.ts:209 iterates rules in declaration order and :195 preserves it, so triggered_rules->>0 is the first rule as declared, not the most severe.

It is correct today only because of this, at rules.ts:667:

export const RULES: Rule[] = [
  ...harmfulIntent,   <- self-harm, spread first
  ...pii,
  ...inappropriate,
];

Swapping two lines in that array literal would stop a self-harm disclosure rendering the crisis card, and no test would fail.

Fix (D11): the predicate scans the whole array for the harm.self family, and the described rule is chosen by severity. Nothing a guardian sees may depend on the order of declarations in a source file.
